# Post-seed API verification checklist

> Generated by `frontend/seed-preparation/scripts/generate.mjs` from the seeded data. Every endpoint below is checked against `backend/api/openapi/openapi.json` by `validate.mjs`. Do not edit by hand.

Run these against the **development or staging API** you seeded, after `provision-accounts.mjs` has set the test-account password. Paths are relative to `/api/v1`.

```bash
API=http://localhost:4000/api/v1; JAR=$(mktemp)
curl -s -c "$JAR" -H "content-type: application/json" -d '{"email":"zainab@kestrel.example","password":"<dev password>"}' "$API/auth/login"
curl -s -b "$JAR" "$API/orgs/kestrel-systems/recruitment/vacancies" | jq .data.total
```

**Database counts and API counts are different things.** The API filters and paginates, so many numbers below are smaller than the row counts in `post-seed-verify.sql`:

| Reason an API number differs from the database | Example |
|---|---|
| Public endpoints show only published, still-open vacancies and events that haven't ended | `/jobs` and `/social/events` depend on the date you check |
| Paginated lists return 20 items by default | Compare `data.total`, not the length of `data.items` |
| Permissions narrow results | A line manager sees only their own and their direct reports' leave |
| The organisation's plan hides whole modules | Amberline (starter) has engagement and payroll rows in the database, but the API returns `403 MODULE_NOT_IN_PLAN` |
| Viewer-specific filters | `/social/people` excludes the viewer and blocked people |
| Totals computed from rows | Event attendees, community members, policy acknowledgements and reactions start at 0 |

Anchor date of this package: **2026-11-09**. If you seed on a different day, regenerate first (see BACKEND_HANDOFF.md), or the date-dependent numbers will be lower.
